# 사용자와 함께 설계하고 개발하기

적용되는 `AGENTS.md`와 저장소 문서를 우선하고 기존 변경을 보존한다.

## 1. 요청과 요구사항 파악

목표, 입력·출력, 사용자 흐름, 제약, 예외, 유지할 동작과 완료 조건을 정리한다. 확인한 사실과 가정을 구분한다.

## 2. 기존 환경 조사

필요한 범위에서 다음을 확인한다.

- 적용 지침과 요구사항 문서
- 저장소 구조, 주요 진입점과 관련 호출 관계
- 언어, 프레임워크, 의존성과 기존 구현 관례
- 빌드·실행·테스트 방법과 관련 테스트
- 설정·환경변수 방식과 현재 변경 파일

관련 영역을 검색한 뒤 필요한 파일을 깊게 읽는다. 기존 방식으로 해결할 수 있으면 새 구조·라이브러리·도구를 추가하지 않는다.

## 3. 계획과 설계

복잡하거나 여러 파일에 걸친 작업은 구현 전에 다음을 짧게 공유한다.

- 이해한 목표와 완료 조건
- 변경할 영역
- 구현 단계와 단계별 검증 방법
- 중요한 가정, 위험 또는 선택지

간단한 작업은 필요한 영역을 확인한 뒤 바로 진행한다. 복잡한 작업은 독립적으로 검증 가능한 단계로 나누되 단계별 승인을 요청받지 않았다면 계획 공유 후 멈추지 않는다.

설계는 다음 순서로 판단한다.

1. 요구사항과 완료 조건 충족
2. 기존 구조와의 일관성
3. 구현·검증의 단순성
4. 오류와 회귀 가능성
5. 유지보수성과 되돌리기 용이성

책임, 데이터 흐름, 상태, 예외, 보안과 테스트 가능성을 고려한다. 확정된 요구사항과 명확한 확장 지점은 고려하되 가상의 미래 기능을 위한 추상화는 만들지 않는다.

중요한 설계 결정은 선택 이유와 포기한 대안을 짧게 알린다. 질문과 진행 여부는 `AGENTS.md`의 기준을 따른다.

새로운 사실로 계획이 달라지면 계획을 갱신한다.

## 4. 단계별 구현

작업 특성에 맞게 다음 항목을 작은 단위로 수행하고 각 단위를 검증한다.

1. 필요한 경우 실패 재현 또는 관련 테스트 작성
2. 핵심 흐름과 필수 예외 상황 구현
3. 관련 테스트 또는 직접 실행
4. 오류·누락 수정과 회귀 확인
5. 전체 흐름 검증과 불필요한 코드 정리

각 단계에서 완료 조건, 기존 동작에 미치는 영향, 입력·출력과 실패 처리를 확인한다. 기존 스타일을 따르고 변경 범위를 작게 유지한다.

## 5. 검증과 문제 해결

완료 전에 diff를 자체 리뷰한다.

- 요구사항 누락과 범위 밖 변경
- 기존 동작의 회귀 가능성
- 입력 검증, 오류 처리와 보안
- 임시 코드와 불필요한 복잡성

변경에 비례해 테스트, 빌드, 정적 검사, 핵심 API·함수 실행과 정상·경계·실패 상황을 검증한다. 수치 계산과 데이터 변환은 필요한 경우 대표 표본으로 직접 대조한다. 도구의 종료 코드뿐 아니라 실제 결과가 완료 조건과 일치하는지 확인한다.

오류가 나면 재현하고 로그와 최근 변경을 확인한다. 근거 없이 여러 영역을 동시에 수정하지 않고 원인을 작은 실험으로 분리한다. 근본 원인을 수정해 같은 방식으로 재검증하고, 같은 접근이 반복해서 실패하면 가정과 해결 방법을 재검토한다. 수행하지 못한 검증은 성공으로 보고하지 않는다.

최신 정보나 API 확인이 필요하면 프로젝트의 실제 버전과 일치하는 공식 문서를 우선한다.

## 6. 서브 에이전트

상위 지침과 실행 환경이 허용할 때만 서브 에이전트를 사용한다. 서로 독립적인 조사·검증을 병렬화할 이점이 분명한 경우로 제한하고, 겹치는 파일을 동시에 수정하지 않도록 경계를 나누며, 주 에이전트가 결과와 코드를 다시 검토한다.

## 7. 소통과 완료 보고

진행 중에는 목표, 현재 단계, 중요한 사실·가정, 발견한 문제와 검증 상태만 짧게 공유한다. 차단 요소가 없으면 계속 진행하며 완료 보고는 `AGENTS.md`의 형식을 따른다.
